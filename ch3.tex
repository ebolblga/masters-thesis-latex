\section{Разработка архитектуры сервиса для программной поддержки генерации расписания учебных заведений}

\subsection{Подход к созданию программного решения}

Для разработки будущего сервиса была выбрана трёхзвенная архитектура (three-tier architecture):

\begin{enumerate}
	\item  База данных (data layer) – слой для хранения исходных данных, требуемых для генерации расписания, а также для хранения уже готовых расписаний.
	\item Сервер (application layer) – на этом слое реализуется вся бизнес-логика и REST API эндпоинты для работы по протоколу HTTP(S).
	\item Клиент (presentation layer) – финальный слой, необходимый для отображения интерфейса сервиса, для удобства взаимодействия с ним через браузер.
\end{enumerate}

Подходом к написания кода было выбрано объектно-ориентированное программирование (ООП). Таким образом все сущности, такие как расписание, учебная аудитория, преподаватель – становятся объектами, обладающими некими параметрами и методами. Это сильно упрощает логику и инкапсулирует сложную логику внутри самих объектов.

\subsection{Формирование архитектуры базы данных}

Прежде чем создавать таблицы базы данных и нормализировать их требуется определиться с данными, которые нужно хранить.

Есть четыре основные сущности:

\begin{itemize}
	\item группа;
	\item преподаватель;
	\item аудитория;
	\item учебное занятие.
\end{itemize}

Каждая из сущностей должна содержать следующие данные:

\begin{enumerate}
	\item Группа (group):
	\begin{itemize}
		\item имя группы;
		\item направления;
		\item институт;
		\item количество студентов.
	\end{itemize}
	
	\item Преподаватель (lecturer):
	\begin{itemize}
		\item институт;
		\item должность;
		\item ФИО.
	\end{itemize}
	
	\item Аудитория (classroom):
	\begin{itemize}
		\item номер аудитории;
		\item вместимость аудитории;
		\item оборудование.
	\end{itemize}
	
	\item Учебное занятие (subject):
	\begin{itemize}
		\item преподаватель;
		\item количество лекций / семинаров / лабораторных занятий;
		\item требуемое оборудование.
	\end{itemize}
\end{enumerate}
