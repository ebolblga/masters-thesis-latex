\section{Реализация сервиса для программной поддержки генерации расписания учебных заведений}

\subsection{Заполнение базы данных}

В идеальном сценарии для заполнения базы данных можно использовать API систем университета, хранящих такие данные как списки групп, преподавателей и учебные планы. Однако на момент написания данной выпускной квалификационной работы такая возможность отсутствует.

Альтернативный вариант --- производить парсинг PDF файлов учебных планов и календарных учебных графиков, которые находятся в открытом доступе на сайте университета \cite{stankin:edu_programs,stankin:calendar}.

Однако существует третий вариант: переиспользовать написанный автором данной выпускной квалификационной работы в бакалавриате парсер \cite{github:grad_work_alpha} PDF файлов расписаний учебных занятий. Хоть это и не будет финальным решением, готовым для запуска системы в работу на пользу учебного заведения --- это будет путём наименьшего сопротивления.

Этот подход также решит две другие проблемы, не имеющие элегантного решения. Тогда, как списки групп можно получить из соответствующего форума в ЭОС ФГБОУ ВО «МГТУ «СТАНКИН» \cite{stankin:groups}, актуальные списки преподавательского состава или таблицы со всеми учебными аудиториями и оборудованием найти не получится. В случае получения данных сразу из готового расписания за прошлый семестр можно определить и какие предметы ведут какие преподаватели, и какие предметы проводятся в каких аудиториях.

\subsubsection{Реализация WFC на языке Polars}

Первым шагом является генерация первичного расписания, удовлетворяющего минимальным требованиям к расписанию учебных занятий. Этот шаг выполняется методом коллапса волновой функции.

Детальное описание алгоритма приведено ниже.

\paragraph{Подготовка таблиц}

\begin{enumerate}
	\item Загрузка из БД множеств групп $G$, преподавателей $L$, дисциплин $S$,
	а также соответствий «группа--дисциплина» ($\mathrm{SubjectGroups}$) и
	«преподаватель--дисциплина» ($\mathrm{SubjectLecturers}$).
	
	\item Отфильтровка дисциплин без назначенного преподавателя.
	После этапа парсинга расписаний встречались предметы без преподавателей,
	и такие случаи требуется проработать в индивидуальном порядке.
	
	\item Построение множества рабочих дней $D$:
	от начала до конца семестра согласно учебному плану, без воскресений.
	
	\item Задание числа пар в день $T=8$ и нумерация слотов
	$t \in \{0,\ldots,T-1\}$.
	
	\item Формирование \textbf{суперпозиции} --- декартова произведения:
	\[
	\mathcal{C}_G = G \times D \times \{0,\ldots,T-1\}, \qquad
	\mathcal{C}_L = L \times D \times \{0,\ldots,T-1\}.
	\]
	Каждая ячейка $(g,d,t)$ или $(\ell,d,t)$ изначально свободна
	($\texttt{subject\_id}=\varnothing$).
	
	\item Вычисление \textbf{веса ячейки} $w(g,d,t)$:
	\[
	w(g,d,t)=\log\!\bigl(1+w_{\mathrm{day}}(\mathrm{weekday}(d))\bigr)\cdot
	w_{\mathrm{slot}}(t),
	\]
	с обнулением в праздники; для занятых ячеек $w(g,d,t)=0$. Именно на этом шаге учитываются предпочтения преподавателей по нагрузке по дням недели, а для студентов двигается распределение --- дневная или вечерняя форма обучения.
	
	\item Вычисление \textbf{энтропии} группы $H(g)$ --- суммарного числа оставшихся
	занятий по всем дисциплинам группы:
	\[
	H(g)=\sum_{s\in S(g)}
	\bigl(n^{\mathrm{лек}}_{g,s}+n^{\mathrm{сем}}_{g,s}+n^{\mathrm{лаб}}_{g,s}\bigr).
	\]
	Аналогично определяется $H(\ell)$ для преподавателей.
\end{enumerate}

\paragraph{Итерация WFC (один шаг \texttt{apply\_one\_step})}

Повторять, пока
\[
\sum_{g\in G}\sum_{s\in S(g)}
\bigl(n^{\mathrm{лек}}_{g,s}+n^{\mathrm{сем}}_{g,s}+n^{\mathrm{лаб}}_{g,s}\bigr)>0.
\]

\begin{enumerate}
	\item Выбор ячейки для коллапса.
	Среди свободных ячеек из $\mathcal{C}_G$ с $H(g)>0$ выбирается множество
	с минимальной энтропией:
	\[
	\mathcal{M}=\arg\min_{(g,d,t)\in\mathcal{C}_G,\;H(g)>0} H(g).
	\]
	Затем случайно выбирается $(g^{*}, d^{*}, t^{*}) \in \mathcal{M}$
	с вероятностями, пропорциональными $\exp(w-\max w)$
	(softmax по весу).
	
	\item Сужение по преподавателям.
	\[
	L^{*}=\{\ell \in L : \exists s \in S(g^{*}),\; (\ell,s)\in\mathrm{SubjectLecturers}\},
	\]
	после чего из этого множества исключаются преподаватели, уже занятые
	в слоте $(d^{*}, t^{*})$:
	\[
	L^{*}\leftarrow \{\ell \in L^{*} : \text{ячейка }(\ell,d^{*},t^{*})\text{ свободна}\}.
	\]
	
	\item Коллапс дисциплины и типа занятия.
	Для каждой пары $(s,c)$, где $c\in\{\mathrm{лек},\mathrm{сем},\mathrm{лаб}\}$,
	для которой $n^c_{g^{*},s}>0$ и существует $\ell\in L^{*}$ такой, что
	$(\ell,s)\in\mathrm{SubjectLecturers}$, выбирается одна тройка
	$(s^{*},c^{*},\ell^{*})$ взвешенным случайным выбором.
	Вес кандидата задаётся как
	\[
	p(\ell)\propto \frac{1}{H(\ell)+\varepsilon},
	\qquad \varepsilon=10^{-6}.
	\]
	
	\item Определение целевых групп.
	\[
	G_{\mathrm{tar}}=
	\begin{cases}
		\{g^{*}\}, & c^{*}\in\{\mathrm{сем},\mathrm{лаб}\},\\[4pt]
		\{g\in G : \text{группа }g\text{ относится к тому же потоку, что и }g^{*}\}, &
		c^{*}=\mathrm{лек},
	\end{cases}
	\]
	где «поток» --- это группа групп с общим префиксом имени
	(например, \texttt{ИДМ-24-} для \texttt{ИДМ-24-08}),
	пересечённая с $S(g)$ для выбранной дисциплины $s^{*}$.
	
	\item Назначение (коллапс).
	Для всех $g\in G_{\mathrm{tar}}$ в ячейку $(g,d^{*},t^{*})$ записывается:
	\[
	(s^{*}, c^{*}, \ell^{*}), \qquad
	\texttt{subject\_type}\in\{0,1,2\}\Leftrightarrow\{\mathrm{лек},\mathrm{сем},\mathrm{лаб}\}.
	\]
	После этого заносится занятость в ячейку преподавателя $(\ell^{*},d^{*},t^{*})$.
	
	\item Локальное распространение ограничений.
	\begin{itemize}
		\item Уменьшить $n^{c^{*}}_{g,s^{*}}$ на 1 для всех $g\in G_{\mathrm{tar}}$;
		\item Уменьшить $H(g)\leftarrow\max(0,H(g)-1)$ для всех $g\in G_{\mathrm{tar}}$;
		\item Обнулить $w$ для занятых ячеек.
	\end{itemize}
	
	\item Недельное распространение (flood fill).
	Пока
	\[
	\min_{g\in G_{\mathrm{tar}}} n^{c^{*}}_{g,s^{*}}>0,
	\]
	для $k=1,2,\ldots,52$ и $\sigma\in\{+1,-1\}$ выполняется попытка
	поставить то же занятие в $(g,d^{*}+\sigma k\text{ нед.},t^{*})$
	для всех $g\in G_{\mathrm{tar}}$, если:
	\begin{itemize}
		\item дата находится в пределах $[d_{\min},d_{\max}]$;
		\item ячейки групп свободны ($\texttt{subject\_id}=\varnothing$);
		\item преподаватель $\ell^{*}$ свободен в этом слоте.
	\end{itemize}
	При успешном назначении повторяется п.~6:
	декрементируются счётчики и обновляется энтропия.
	
	\item Распределение аудиторий для занятий.
	Для всех аудиторий заранее вычисляется матрица кратчайших расстояний
	$\mathrm{Dist}(a_i,a_j)$ (см. \figref{fig:matrix}).
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=1\textwidth]{images/ch5/matrix.png}
		\caption{Матрица примерных расстояний между аудиториями}
		\label{fig:matrix}
	\end{figure}
	
	\item Для назначенного занятия $(g,d,t,s,c,\ell)$ строится множество допустимых аудиторий:
	\[
	A_{\mathrm{adm}}(g,d,t,s,c)=
	\bigl\{
	a \in A :
	\mathrm{cap}(a)\ge |G_{\mathrm{tar}}|,\;
	\mathrm{equip}(a)\supseteq \mathrm{lab\_equipment}(s,c),\;
	a \text{ свободна в слоте } (d,t)
	\bigr\}.
	\]
	
	\item Выбор аудитории выполняется жадным образом с учётом уже назначенных занятий
	в тот же день $d$ для группы $g$:
	
	\begin{itemize}
		\item если для дня $d$ это первое занятие группы $g$,
		выбирается первая аудитория из $A_{\mathrm{adm}}$, отсортированного
		в лексикографическом порядке по номеру аудитории;
		
		\item если в этот день уже назначена хотя бы одна аудитория
		$a_{\mathrm{prev}}$ для группы $g$, то множество $A_{\mathrm{adm}}$
		сортируется по возрастанию расстояния
		$\mathrm{Dist}(a_{\mathrm{prev}}, a)$, и выбирается первая
		допустимая аудитория.
	\end{itemize}
	
	\item Таким образом достигается двойная цель:
	минимизация числа используемых аудиторий за счёт устойчивого закрепления
	аудиторий за группами и минимизация перемещений внутри корпуса
	за счёт локальной оптимизации переходов между последовательными занятиями.
\end{enumerate}

\paragraph{Завершение WFC}

\begin{enumerate}
	\item Остановка происходит, когда все счётчики
	$n^{\mathrm{лек}}$, $n^{\mathrm{сем}}$, $n^{\mathrm{лаб}}$
	обнуляются.
	
	\item $\mathcal{C}_G$ и $\mathcal{C}_L$ сохраняются как итоговое расписание.
\end{enumerate}

\subsection{Вывод по пятой главе}

Была реализована программная основа сервиса для генерации расписания учебных занятий. Для системы была реализована трёхзвенная архитектура, обеспечивающая разделение ответственности между хранилищем данных, серверной логикой и пользовательским интерфейсом. Был подготовлен механизм заполнения БД на основе доступных источников данных.

На стороне сервера реализована бизнес-логика и REST API для взаимодействия с клиентской частью и внешними компонентами системы. На стороне клиента разработано веб-приложение, позволяющее удобно работать с сервисом через браузер. В результате получена работоспособная система, пригодная для дальнейшего развития и последующей интеграции в более полный процесс автоматизированного формирования расписания.
